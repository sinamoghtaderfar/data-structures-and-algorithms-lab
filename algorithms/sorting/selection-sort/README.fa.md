# مرتب‌سازی انتخابی

[English version](README.md)

در این بخش الگوریتم مرتب‌سازی انتخابی را با پایتون پیاده‌سازی کردم و فقط به نوشتن تابع اصلی بسنده نکردم. برای اینکه رفتار الگوریتم را بهتر ببینم، مراحل اجرا را ذخیره کردم، برای آن نمایش تصویری ساختم و زمان اجرا را هم روی ورودی‌های بزرگ‌تر اندازه گرفتم.

## ایده اصلی

در هر مرحله، کوچک‌ترین مقدار از بخش باقی‌مانده پیدا می‌شود و به قسمت مرتب‌شده منتقل می‌شود.

مثلاً از این لیست شروع می‌کنیم:

```text
[5, 3, 6, 2, 10]
```

در مرحله اول کوچک‌ترین مقدار `2` است:

```text
مرتب‌شده:
[2]

باقی‌مانده:
[5, 3, 6, 10]
```

بعد `3` انتخاب می‌شود:

```text
مرتب‌شده:
[2, 3]

باقی‌مانده:
[5, 6, 10]
```

این روند ادامه پیدا می‌کند تا بخش باقی‌مانده خالی شود.

## پیاده‌سازی

برای اینکه منطق کد واضح‌تر باشد، کار را به دو تابع تقسیم کردم.

تابع اول:

```text
find_smallest(arr)
```

کل لیست را بررسی می‌کند و شماره جایگاه کوچک‌ترین مقدار را برمی‌گرداند.

برای نمونه:

```python
find_smallest([5, 3, 6, 2, 10])
```

نتیجه:

```text
3
```

است، چون مقدار `2` در جایگاه شماره `3` قرار دارد.

تابع اصلی:

```text
selection_sort(arr)
```

هر بار کوچک‌ترین مقدار را پیدا می‌کند، آن را از نسخه کپی‌شده‌ی ورودی برمی‌دارد و به لیست نتیجه اضافه می‌کند.

قبل از شروع مرتب‌سازی از ورودی یک کپی ساخته می‌شود. به همین دلیل لیست اصلی بعد از اجرای الگوریتم تغییر نمی‌کند.

```python
numbers = [5, 3, 6, 2, 10]

sorted_numbers = selection_sort(numbers)

print(sorted_numbers)
print(numbers)
```

خروجی:

```text
[2, 3, 5, 6, 10]
[5, 3, 6, 2, 10]
```

## چرا زمان اجرا درجه دوم است؟

برای پیدا کردن کوچک‌ترین مقدار باید بخش باقی‌مانده بررسی شود.

تقریباً چنین تعداد مقایسه‌ای داریم:

```text
n + (n - 1) + (n - 2) + ... + 1
```

به همین دلیل مرتبه زمانی الگوریتم برابر است با:

```text
O(n²)
```

در این نسخه هنگام حذف از لیست پایتون ممکن است عناصر بعدی نیز جابه‌جا شوند، اما مرتبه کلی الگوریتم همچنان درجه دوم باقی می‌ماند.

این پیاده‌سازی درجا نیست، چون هم یک کپی از ورودی ساخته می‌شود و هم یک لیست جدید برای نتیجه داریم.

## بررسی زمان اجرا

برای اینکه رشد زمانی را فقط به صورت تئوری نبینم، الگوریتم را با چند اندازه ورودی اجرا کردم.

یکی از اجراها این نتیجه را داد:

| تعداد عناصر | زمان اجرا |
| ---: | ---: |
| 200 | 0.000692 ثانیه |
| 400 | 0.002488 ثانیه |
| 800 | 0.011731 ثانیه |
| 1600 | 0.049762 ثانیه |

این اعداد روی سیستم‌های مختلف یا حتی بین چند اجرای پشت‌سرهم می‌توانند کمی فرق کنند. چیزی که اهمیت دارد الگوی رشد آن‌هاست.

تقریباً هر بار که تعداد عناصر دو برابر شد، زمان اجرا نزدیک به چهار برابر افزایش پیدا کرد. همین رفتار چیزی است که از یک الگوریتم با پیچیدگی درجه دوم انتظار داریم.

![نمودار زمان اجرای مرتب‌سازی انتخابی](assets/selection_sort_benchmark.png)

## تست‌ها

برای بررسی حالت‌های مختلف از:

```text
pytest
```

استفاده کردم.

تست‌ها فقط یک ورودی معمولی را بررسی نمی‌کنند. حالت‌هایی مثل لیست خالی، یک عنصر، ورودی از قبل مرتب‌شده، ترتیب معکوس، مقادیر تکراری و اعداد منفی هم پوشش داده شده‌اند.

همچنین یک تست جدا بررسی می‌کند که لیست اصلی بعد از مرتب‌سازی تغییر نکرده باشد.

برای اجرای تست‌ها:

```bash
pytest algorithms/sorting/selection-sort/test_selection_sort.py -v
```

## چیزی که از این تمرین یاد گرفتم

مرتب‌سازی انتخابی از نظر عملی الگوریتمی نیست که برای داده‌های بزرگ انتخاب کنم، اما برای فهمیدن هزینه الگوریتم‌ها تمرین خوبی بود.

مهم‌ترین بخش برای من مقایسه زمان اجرا بود. وقتی اندازه ورودی دو برابر شد، زمان اجرا فقط دو برابر نشد و خیلی سریع‌تر رشد کرد. این باعث شد مفهوم پیچیدگی درجه دوم از حالت یک فرمول خارج شود و در اجرای واقعی دیده شود.

نمایش تصویری هم کمک کرد منطق الگوریتم ساده‌تر دیده شود: در هر مرحله فقط یک کار انجام می‌دهیم؛ کوچک‌ترین مقدار باقی‌مانده را پیدا می‌کنیم و به بخش مرتب‌شده اضافه می‌کنیم.
