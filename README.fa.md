# آزمایشگاه ساختمان داده و الگوریتم‌ها

این repository فضای شخصی من برای مطالعه و تمرین **ساختمان داده‌ها و الگوریتم‌ها (Data Structures & Algorithms)** است.

این پروژه را ساختم تا چیزهایی را که از کتاب‌ها و منابع مختلف یاد می‌گیرم در یک جای منظم نگه دارم و در کنار مطالعه‌ی مفاهیم، آن‌ها را پیاده‌سازی، تست و تمرین کنم.

مطالب مربوط به یادگیری از پیاده‌سازی‌های اصلی جدا نگهداری می‌شوند. به این ترتیب می‌توانم یک مفهوم را در کتاب‌های مختلف مطالعه کنم، در حالی که کد آن بر اساس خود موضوع مرتب باقی می‌ماند.

---

## روش مطالعه

مسیر کلی مطالعه‌ی من:

```text
یادگیری
  ↓
پیاده‌سازی
  ↓
تست
  ↓
بررسی
  ↓
تمرین
```

ابتدا مفهوم و پیچیدگی زمانی و فضایی آن را مطالعه می‌کنم، سپس آن را با Python پیاده‌سازی و تست می‌کنم.

در جاهایی که مفید باشد، از visualization یا benchmark برای بررسی بهتر رفتار الگوریتم و از challenge برای تمرین همان مفهوم در مسئله‌های متفاوت استفاده می‌کنم.

---

## ساختار Repository

```text
.
├── algorithms/
├── data-structures/
├── challenges/
├── learning/
├── README.md
├── README.fa.md
├── requirements.txt
├── SOURCES.md
└── LICENSE
```

هر بخش از repository وظیفه‌ی مشخصی دارد.

### `learning/`

مطالبی که هنگام مطالعه‌ی کتاب‌ها و منابع مختلف ایجاد می‌کنم در این فولدر قرار می‌گیرند.

هر کتاب می‌تواند فولدر مخصوص خودش را داشته باشد:

```text
learning/
├── fundamentals/
├── grokking-algorithms/
└── <book-name>/
```

یادداشت‌ها، توضیحات و تمرین‌هایی که مستقیماً به یک کتاب یا فصل مربوط هستند در این بخش باقی می‌مانند.

به این ترتیب مطالب مربوط به یادگیری به منبع اصلی خودشان متصل می‌مانند.

---

### `algorithms/`

پیاده‌سازی اصلی الگوریتم‌هایی که مطالعه می‌کنم در این فولدر قرار می‌گیرد.

الگوریتم‌ها بر اساس موضوع دسته‌بندی می‌شوند، نه بر اساس کتاب:

```text
algorithms/
├── searching/
├── sorting/
├── graph/
└── ...
```

هر الگوریتم می‌تواند فولدر مخصوص خودش را داشته باشد:

```text
algorithms/
└── searching/
    └── binary-search/
        ├── implementation
        ├── tests
        ├── documentation
        └── visualization
```

Binary Search فعلی یک نمونه از این ساختار است:

[`algorithms/searching/binary-search/`](./algorithms/searching/binary-search/)

اگر بعداً همان الگوریتم را در کتاب دیگری مطالعه کنم، مطالب مربوط به آن کتاب در `learning/` قرار می‌گیرند، در حالی که پیاده‌سازی اصلی الگوریتم همچنان در این بخش باقی می‌ماند.

---

### `data-structures/`

پیاده‌سازی و بررسی ساختمان داده‌ها در این فولدر قرار می‌گیرد.

ساختمان داده‌ها بر اساس خود مفهوم دسته‌بندی می‌شوند:

```text
data-structures/
├── linked-lists/
├── stacks/
├── queues/
├── hash-tables/
├── trees/
├── graphs/
└── ...
```

مثل الگوریتم‌ها، ساختمان داده‌ها نیز مستقل از کتابی که آن‌ها را در آن مطالعه می‌کنم سازمان‌دهی می‌شوند.

---

### `challenges/`

مسئله‌هایی که در آن‌ها مفاهیم مطالعه‌شده را تمرین و استفاده می‌کنم در این فولدر قرار می‌گیرند.

```text
challenges/
├── binary-search/
├── sorting/
└── ...
```

تمرین‌هایی که مستقیماً متعلق به یک کتاب یا فصل هستند در `learning/` باقی می‌مانند.

`challenges/` برای مسئله‌هایی است که در آن‌ها یک مفهوم را مستقل از ساختار یک کتاب تمرین می‌کنم یا در مسئله‌ای متفاوت به کار می‌برم.

Challengeها بر اساس مفهوم اصلی مسئله دسته‌بندی می‌شوند. یک challenge ممکن است از چند الگوریتم یا ساختمان داده استفاده کند، اما در فولدری قرار می‌گیرد که مفهوم اصلی مورد تمرین را نشان می‌دهد.

---

### [`SOURCES.md`](./SOURCES.md)

کتاب‌ها و منابعی که در طول مطالعه استفاده می‌کنم در این فایل ثبت می‌شوند.

جدا بودن منابع کمک می‌کند منبع مطالب یادگیری مشخص باشد، بدون اینکه ساختار اصلی repository به یک کتاب خاص وابسته شود.

## ساختار کلی Repository

```text
کتاب‌ها و منابع
       │
       ▼
    learning/
       │
       ▼
 یادگیری و تمرین
       │
   ┌───┴────────────┐
   ▼                ▼
algorithms/   data-structures/
   │                │
   └───────┬────────┘
           ▼
       challenges/
```

به زبان ساده:

- `learning/` — مطالعه و مطالب مربوط به کتاب‌ها
- `algorithms/` — پیاده‌سازی الگوریتم‌ها
- `data-structures/` — پیاده‌سازی و بررسی ساختمان داده‌ها
- `challenges/` — تمرین و استفاده از چیزهایی که یاد گرفته‌ام

این نمودار ساختار محتوای repository را نشان می‌دهد.

فرایند مطالعه‌ی من — **یادگیری → پیاده‌سازی → تست → بررسی → تمرین** — در بخش [روش مطالعه](#روش-مطالعه) توضیح داده شده است.

این ساختار باعث می‌شود repository به یک کتاب خاص وابسته نباشد و هر نوع محتوا جای مشخص خودش را داشته باشد.

## اجرای پروژه

ساخت virtual environment:

```bash
python -m venv .venv
```

فعال کردن آن:

**Linux / macOS**

```bash
source .venv/bin/activate
```

**Windows PowerShell**

```powershell
.venv\Scripts\Activate.ps1
```

نصب dependencyها:

```bash
pip install -r requirements.txt
```

اجرای تمام تست‌ها:

```bash
pytest
```
