# چالش Binary Search — جست‌وجوی لاگ سرور

در این چالش، از Binary Search برای حل یک مسئله‌ی واقعی‌تر روی لاگ‌های مرتب‌شده‌ی سرور استفاده می‌کنیم.

هدف این است که فقط یک عدد دقیق را داخل آرایه پیدا نکنیم، بلکه مفهوم Binary Search را برای یک مسئله‌ی متفاوت تطبیق بدهیم.

---

## مسئله

فرض کنید یک سرور، لاگ‌های خود را به ترتیب زمانی ذخیره می‌کند.

هر لاگ شامل دو بخش است:

```text
(timestamp, message)
```

مثال:

```python
logs = [
    ("10:00:01", "Server started"),
    ("10:02:15", "User login"),
    ("10:05:40", "Payment request"),
    ("10:08:12", "Database warning"),
    ("10:08:48", "Server warning"),
    ("10:12:33", "User logout"),
]
```

تابعی بنویسید که یک `target_time` دریافت کند و **اولین لاگی را پیدا کند که زمان آن برابر یا بعد از زمان موردنظر باشد**.

یعنی باید اولین timestamp را پیدا کنیم که شرط زیر را داشته باشد:

```text
timestamp >= target_time
```

راه‌حل باید با استفاده از **Binary Search** نوشته شود.

---

## مثال ۱ — زمان دقیق وجود دارد

ورودی:

```python
target_time = "10:08:12"
```

این زمان دقیقاً داخل لیست وجود دارد:

```text
Index:  0         1         2         3
Time:   10:00:01  10:02:15  10:05:40  10:08:12
                                      ↑
```

خروجی مورد انتظار:

```text
3
```

---

## مثال ۲ — زمان دقیق وجود ندارد

ورودی:

```python
target_time = "10:08:15"
```

در لیست لاگی دقیقاً با زمان `10:08:15` وجود ندارد.

دو زمان اطراف آن:

```text
10:08:12
10:08:48
```

هستند.

`10:08:12` قبل از زمان موردنظر است.

اولین زمانی که شرط زیر را برقرار می‌کند:

```text
timestamp >= target_time
```

این مقدار است:

```text
10:08:48
```

پس خروجی مورد انتظار:

```text
4
```

چون:

```python
logs[4]
```

برابر است با:

```python
("10:08:48", "Server warning")
```

---

## مثال ۳ — زمان موردنظر قبل از همه‌ی لاگ‌هاست

ورودی:

```python
target_time = "09:30:00"
```

اولین لاگ موجود:

```text
10:00:01
```

از زمان موردنظر بزرگ‌تر است.

پس خروجی مورد انتظار:

```text
0
```

---

## مثال ۴ — هیچ لاگ معتبری وجود ندارد

ورودی:

```python
target_time = "23:00:00"
```

هیچ لاگی در ساعت `23:00:00` یا بعد از آن وجود ندارد.

پس خروجی:

```text
None
```

---

## محدودیت

راه‌حل نباید لاگ‌ها را یکی‌یکی بررسی کند.

مثلاً استفاده از جست‌وجوی خطی مانند:

```python
for log in logs:
    ...
```

در بدترین حالت پیچیدگی:

```text
O(n)
```

خواهد داشت.

هدف این چالش این است که مزیت اصلی Binary Search حفظ شود:

```text
O(log n)
```

---

## ایده‌ی اصلی

Binary Search معمولی معمولاً دنبال یک مقدار دقیق می‌گردد.

مثلاً:

```text
guess == target
→ return index
```

اما در این چالش ممکن است مقدار دقیق اصلاً وجود نداشته باشد.

مثلاً:

```text
target = 10:08:15
```

اما زمان‌های موجود:

```text
10:08:12
10:08:48
```

باشند.

در این حالت باید `10:08:48` را پیدا کنیم.

پس هنگام جست‌وجو، بعضی از مقادیر می‌توانند به‌عنوان **جواب احتمالی** در نظر گرفته شوند.

---

## Candidate

اگر:

```text
guess > target_time
```

باشد، log فعلی می‌تواند یک جواب معتبر باشد.

اما ممکن است در سمت چپ یک log نزدیک‌تر به `target_time` وجود داشته باشد.

پس index فعلی را به‌عنوان یک **candidate** ذخیره می‌کنیم و جست‌وجو را در سمت چپ ادامه می‌دهیم.

به‌صورت مفهومی:

```text
guess > target

        ↓

ذخیره index فعلی
به‌عنوان candidate

        ↓

ادامه‌ی جست‌وجو
در نیمه‌ی چپ
```

اگر بعداً candidate بهتری پیدا شود، مقدار قبلی جایگزین می‌شود.

---

## تصمیم‌های Binary Search

در هر مرحله سه حالت داریم.

### Guess کوچک‌تر از target است

```text
guess < target_time
```

مقدار فعلی و تمام مقادیر سمت چپ آن بیش از حد زود هستند.

پس باید سمت راست را جست‌وجو کنیم:

```text
low = mid + 1
```

---

### Guess دقیقاً برابر target است

```text
guess == target_time
```

زمان دقیق پیدا شده است.

پس index آن را برمی‌گردانیم.

---

### Guess بزرگ‌تر از target است

```text
guess > target_time
```

log فعلی می‌تواند جواب باشد.

پس ابتدا آن را به‌عنوان candidate ذخیره می‌کنیم:

```text
candidate = mid
```

بعد سمت چپ را بررسی می‌کنیم:

```text
high = mid - 1
```

چون ممکن است جواب بهتری وجود داشته باشد.

---

## مثال اجرای الگوریتم

فرض کنیم:

```text
target = 10:08:15
```

و زمان‌ها این‌ها باشند:

```text
10:00:01
10:02:15
10:05:40
10:08:12
10:08:48
10:12:33
```

Binary Search ممکن است این‌طور اجرا شود:

```text
Step 1

guess = 10:05:40

10:05:40 < 10:08:15

→ جست‌وجو در سمت راست
```

بعد:

```text
Step 2

guess = 10:08:48

10:08:48 > 10:08:15

→ candidate = index 4
→ جست‌وجو در سمت چپ
```

بعد:

```text
Step 3

guess = 10:08:12

10:08:12 < 10:08:15

→ جست‌وجو در سمت راست
```

در این مرحله محدوده‌ی جست‌وجو خالی می‌شود.

بهترین candidate پیدا‌شده:

```text
index 4
```

است.

که مربوط به این log می‌شود:

```python
("10:08:48", "Server warning")
```

---

## پیچیدگی

Binary Search بعد از هر مقایسه تقریباً نصف فضای جست‌وجو را حذف می‌کند.

بنابراین:

```text
Time Complexity: O(log n)
```

الگوریتم فقط چند متغیر اضافی مثل:

```text
low
high
mid
candidate
```

نیاز دارد.

پس حافظه‌ی اضافی آن ثابت است:

```text
Space Complexity: O(1)
```

## تست‌های پیشنهادی

حالت‌های خوبی که می‌توان برای این چالش تست کرد:

* زمان دقیق وجود داشته باشد
* target بین دو timestamp قرار داشته باشد
* target قبل از اولین log باشد
* target بعد از آخرین log باشد
* لیست خالی باشد
* فقط یک log وجود داشته باشد

---

## چیزی که از این چالش یاد گرفتم

این چالش Binary Search ساده‌ی فصل اول را یک مرحله جلوتر می‌برد.

در اینجا فقط دنبال یک مقدار دقیق نیستیم.

بلکه می‌خواهیم اولین مقداری را پیدا کنیم که شرط زیر را داشته باشد:

```text
value >= target
```

نکته‌ی مهم این است که Binary Search فقط یک تکه کد برای حفظ کردن نیست.

مهارت اصلی، درک نحوه‌ی استفاده از:

```text
low
high
mid
```

برای حذف امن بخشی از یک فضای جست‌وجوی مرتب است.

متغیر `candidate` نیز کمک می‌کند یک جواب معتبر را نگه داریم و همزمان برای پیدا کردن جواب بهتر به جست‌وجو ادامه دهیم.

---

## نتیجه‌ی اصلی

سؤال Binary Search معمولی این است:

> آیا این مقدار دقیق داخل مجموعه وجود دارد؟

اما این چالش سؤال متفاوتی می‌پرسد:

> اولین مقداری که برابر یا بزرگ‌تر از target است کدام است؟

هر دو مسئله همچنان می‌توانند با پیچیدگی:

```text
O(log n)
```

حل شوند، چون داده‌ها مرتب هستند و بعد از هر مقایسه می‌توانیم تقریباً نصف فضای جست‌وجو را حذف کنیم.
